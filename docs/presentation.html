The LLM Wiki

context/ is the shared brain every agent reads before it does anything else. Instrumentation and Context write to it; Analysis only ever reads it — that split is what stops a stale schema assumption from quietly becoming a wrong answer.

Agent 1

Instrumentation Agent

  1. Read the context layer — understand entities and existing conventions first
  2. Load ClickHouse best-practices skills — the same rules that keep schema and query design efficient, applied automatically, not from memory
  3. Design + apply the schema from spec + raw NDJSON (human-in-the-loop)
  4. Verify the table was created and data inserted correctly
  5. Record the change as a durable, reviewable file
● ddl.sql
● justification.md
● profile.md
● load_report.md

Result: tables designed with the right ordering keys, types, and partitioning from day one — not a schema someone has to fix later.

Agent 2

Context Agent — the wiki,
bootstrapped from real data.

context/
├── index.md — entry point
├── business.md — north-star metric, funnel
├── tables/ — one file per table
├── metrics/ — one file per metric
├── known-issues/ — quirks, broken joins
└── relationship.md — join map

One file per concern — diffs stay readable, agents update a single page instead of rewriting everything.

Bootstrap · runs before everything else

The base context we're handed isn't trusted blindly. A one-time pass — repeated whenever new tables land — uses the ClickHouse MCP server to check it against the real event tables, before the wiki is built.

Runs twice per spec: Pass 1 publishes new schema/known-issues before Analysis runs. Pass 2 consolidates every finding after — one single writer, so nothing races.

Agent 3

Analysis Agent

  1. Reads the context layer, the spec, and the PM's questions
  2. Runs once per question, all concurrently, read-only against context/
  3. Produces a report grounded in verified schema and known issues

● analysis/q02_report.html
● analysis/qNN.md …

Concurrent and read-only on purpose — nothing writes to the wiki mid-flight.
