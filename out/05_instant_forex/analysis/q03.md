## Question
Where is the drop — offer → amount_entered, or added_to_cart → purchased?

## Answer
The drop is overwhelmingly at **offer → amount_entered**: of 2,900 users shown the forex offer (`forex_offer_shown`), only 1,033 reach `amount_entered` — a **64.38% drop (1,867 users lost)**, step-through 35.62%. By contrast, `forex_added_to_cart → forex_purchased` loses only **24.69% (179 users)**, step-through 75.31% (725 → 546).

Drilling into the first segment: `currency_selected` and `amount_entered` are exactly the same 1,033 users (100% step-through, confirmed by direct set-membership join, not just matching row counts) — so **the entire offer→amount_entered leak happens at the very first step, `forex_offer_shown → currency_selected`** (only 35.62% of users who see the offer even engage the currency picker). Once a user picks a currency, they always enter an amount.

Full funnel, verified live by `uniqExact(user_id)` set-membership joins (per known_issues.md D1 — `windowFunnel` is not used here, and this funnel was confirmed **perfectly nested**: every downstream stage's users are a 100% subset of the prior stage, all the way back to `forex_offer_shown`):

| Stage | Users | Step-through | Drop-off | Users lost |
|---|---:|---:|---:|---:|
| `forex_offer_shown` | 2,900 | — | — | — |
| `currency_selected` | 1,033 | 35.62% | **64.38%** | **1,867** |
| `amount_entered` | 1,033 | 100% | 0% | 0 |
| `forex_added_to_cart` | 725 | 70.18% | 29.82% | 308 |
| `forex_purchased` | 546 | 75.31% | 24.69% | 179 |

Overall attach rate `forex_purchased` ÷ `forex_offer_shown` = 546/2,900 = 18.83%.

Scope/caveats: this is spec 05's (Instant Forex Add-on) standalone sample, 2026-06-08→2026-06-28, 2,900 offer-shown rows; per known_issues.md D2, all 5 tables' `application_id` has 0% overlap with `application_started`, so this cannot be joined to the main visa funnel — treat it as a standalone add-on flow. This is also the first `analysis/qNN.md` file for spec 05, so it upgrades the `tables/index.md`/`forex_*.md` step-through figures from "unverified row-count ratios" to verified set-membership joins for every transition above.
