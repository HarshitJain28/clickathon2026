## Question
Is per-traveller document completion (`docs_complete`) the bottleneck for big groups?

## Answer
No — group size itself is the dominant driver of the `group_started → group_submitted` drop-off, and `docs_complete` explains only a small slice of it, if any.

**The size effect is large and monotonic.** Set-membership completion rate (`group_submitted.group_id` ⊆ `group_started.group_id` by construction, so no windowFunnel/D1 risk) by `group_size`:

| group_size | groups started | groups submitted | submission rate |
|---:|---:|---:|---:|
| 2 | 475 | 330 | 69.47% |
| 3 | 283 | 166 | 58.66% |
| 4 | 238 | 120 | 50.42% |
| 5 | 114 | 44 | 38.60% |
| 6 | 90 | 28 | 31.11% |

Submission rate falls **38.4 points** (69.47% → 31.11%, a 55% relative decline) from size 2 to size 6.

**`docs_complete` barely moves with group size**, so it can't be driving that trend. Per-traveller completion rate (`traveller_added.docs_complete`) by `group_size`: 81.15% (2) → 80.52% (3) → 80.32% (4) → 77.78% (5) → 78.41% (6) — only a 2.7-point spread, no meaningful degradation as groups get bigger.

**Within each size bucket, having every added traveller's docs complete doesn't reliably predict submission either.** Grouping `traveller_added` by `group_id` and flagging groups where *all* added travellers have `docs_complete = true`, then checking submission rate:

| group_size | submit rate, all docs complete | submit rate, not all complete | gap |
|---:|---:|---:|---:|
| 2 | 66.98% | 74.68% | **−7.7pp** (reversed) |
| 3 | 56.33% | 61.60% | **−5.3pp** (reversed) |
| 4 | 56.88% | 44.96% | +11.9pp |
| 5 | 41.46% | 36.99% | +4.5pp |
| 6 | 37.50% | 28.79% | +8.7pp |

For small groups (2–3), submission is actually *higher* when not all travellers' docs are complete — the opposite of what a "docs bottleneck" hypothesis predicts (plausibly because incomplete-docs groups there are still early/short and haven't stalled yet). Only for big groups (4–6) does the direction flip to the expected sign, but the gap tops out at ~12 points — a third the size of the ~38-point drop attributable to group size alone. Even a size-6 group with 100% docs complete only submits 37.5% of the time, far below a size-2 group's 66.98% baseline regardless of doc status.

**Conclusion:** big groups do complete less often, but `docs_complete` is at most a minor contributing factor, not the bottleneck — something else about coordinating more travellers (not captured by this flag) is driving most of the size effect.

Scope: Group/Family spec 02 sample, 1,200 `group_started` rows / 3,495 `traveller_added` rows, 2026-06-08 → 2026-06-28. Per D2, `application_id` on these tables has 0% overlap with `application_started` — this cannot be joined to the main funnel and is analysed standalone. Per D1, `group_started → group_submitted` completion was computed by verified set membership (valid here since `group_submitted`'s `group_id`s are a subset of `group_started`'s by construction), not `windowFunnel`.
